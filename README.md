# Captain supply analysis

This submission answers two supply questions for Rapido:

- **Part A:** where the captain onboarding funnel loses people, which fixes are practical, and whether WA002 should be scaled.
- **Part B:** when the airport marketplace is short, whether the trip data points to a return-utilisation problem, and whether airport acquisition should start now.

## Submission contents

The recruiter-facing folder contains only the following items:

```text
Part-A_analysis.ipynb       Part A working, explained cell by cell
Part-B_analysis.ipynb       Part B working, explained cell by cell
app.py                      Streamlit dashboard
utils.py                    Shared loading, validation, and calculations
README.md                   This guide
deliverables/
├── memo.pdf                Two-page executive decision memo
└── presentation.pdf        Six-slide presentation deck
```

The raw `Data/` folder must stay beside these files when rerunning the analysis. It contains the original CSV inputs and is never overwritten. The `outputs/` folder is generated by the notebooks and supplies the tables and charts read by the dashboard.

## How the files work together

The notebooks are the analytical working. They read the raw CSVs, validate them through `utils.py`, calculate the results, save tables and charts under `outputs/`, and refresh the two general files in `deliverables/`.

The dashboard does not execute the notebooks. It reads the validated notebook exports through `utils.py`, checks the raw-file hashes, and presents the same results in two tabs. This keeps the dashboard fast and prevents it from silently showing results produced from different CSVs.

```text
Data/*.csv
   ↓
Part-A_analysis.ipynb  +  Part-B_analysis.ipynb
   ↓
outputs/part_a/ and outputs/part_b/
   ↓
app.py  →  utils.py  →  dashboard
```

## Setup

Use Python 3.12 or a compatible recent Python version. From the project folder:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install pandas numpy scipy scikit-learn matplotlib seaborn nbformat nbclient ipykernel nbconvert reportlab python-pptx streamlit
```

In VS Code, open each notebook and select `.venv/bin/python` as the notebook kernel.

## Run the working

Run both notebooks from top to bottom, in this order:

1. Open `Part-A_analysis.ipynb` and choose **Run All**.
2. Open `Part-B_analysis.ipynb` and choose **Run All**.

The notebooks are also executable from the project directory:

```bash
.venv/bin/python -m jupyter nbconvert --to notebook --execute --inplace Part-A_analysis.ipynb
.venv/bin/python -m jupyter nbconvert --to notebook --execute --inplace Part-B_analysis.ipynb
```

Part A includes model sensitivity checks and a 300-resample campaign bootstrap, so it takes longer than a simple CSV summary. Part B uses 2,000 calendar-day bootstrap resamples. The notebooks record input hashes, package versions, seeds, and analysis rules in their run manifests.

## Run the dashboard

Run the notebooks first, then start Streamlit:

```bash
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1
```

Open `http://localhost:8501`. The dashboard has two tabs:

- **Onboarding:** funnel, segment comparisons, document-quality opportunities, WA002 evidence, recommendations, data-quality notes, and links to the general memo and deck.
- **Airport supply:** hourly shortage, month validation, trip outcomes, pilot sizing, and data-quality notes.

## Analysis definitions and assumptions

- **Onboarding outcome:** approval and first order within 30 elapsed days of signup. The main cohort is January–May signups because June does not have a complete 30-day follow-up window.
- **Document funnel:** stages are reconstructed from event timestamps. A captain's first unpassed required document owns the loss. ERickshaw skips Permit.
- **WA002:** recipients and controls are aligned after the Registration Certificate step. The reported adjusted difference is an association, not proof that the message caused the improvement. A randomized test at that stage is required before scale-up.
- **Airport marketplace:** the hourly file is used for demand and fulfilment. The trip file is a separate sample and is not multiplied into marketplace totals.
- **Airport pilot:** the 20-slot, 28-night scenario assumes 80% attendance, 0.75 completed requests per effective captain-hour, INR 30 per available hour, and a bounded INR 60 fallback. These are planning assumptions, not a permanent business case.
- **Costs:** illustrative variable costs exclude fixed engineering, airport fees, acquisition bonuses, and captain earnings.

## Decision in one paragraph

Fix onboarding completion before buying more reach: start an Insurance handoff pilot and guided document recapture, while holding blanket WA002 scaling. At the airport, run a timed night-supply and return-utilisation pilot before funding a catchment signup bonus. The decision should change only after randomized results show incremental approvals or fulfilments, acceptable quality and complaints, stronger return utilisation, and Finance-approved unit economics.

## Known data limits

The onboarding files contain summary/event mismatches and clicked-but-undelivered messages; those are reported instead of silently corrected. The airport hourly data do not include flight schedules, queue position, dispatch events, unique captains, completion timestamps, or earnings. The trip sample is not a validated subset of hourly completed trips, so it supports a directional operational hypothesis rather than an acquisition ROI claim.
